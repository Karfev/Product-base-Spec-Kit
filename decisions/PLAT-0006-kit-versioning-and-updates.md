# PLAT-0006: Версия фреймворка и обновление форков через git

## Контекст и постановка проблемы

У фреймворка не было номера версии, а форк не мог получить исправления иначе как вручную.
У `AIS-by-Specs` за время с момента форка накопились локальные правки конституции, `check-trace.py` и схемы, поэтому слепая перезапись потеряла бы их.
Обновления получают только свои репозитории, в том числе в закрытом контуре без доступа к публичным реестрам пакетов.

## Факторы принятия решения

- **Локальные правки не теряются молча:** их должно быть видно до коммита.
- **Без новых зависимостей:** достаточно bash и git, источником может быть локальный клон.
- **Простота:** отдельный формат состояния пришлось бы поддерживать и восстанавливать при сбоях.

## Рассмотренные варианты

- **Вариант A:** npm- или pip-пакет с установщиком. Требует реестра пакетов, для своих репозиториев это избыточно.
- **Вариант B:** Lock-файл с хешами файлов, как у генераторов шаблонов. Дублирует то, что git уже знает, и может разойтись с ним.
- **Вариант C:** Тег версии и `git checkout <тег> -- <пути>` по списку путей. Результат остаётся незакоммиченным.
- **Вариант D:** `git merge` тега. Истории форка и кита разошлись, а контент инициатив конфликтовал бы с шаблонами.

## Решение

**Выбранный вариант: C.**

- `VERSION` и `CHANGELOG.md` хранят версию, тег релиза — `kit-vX.Y.Z`.
- `tools/kit-paths.txt` перечисляет пути фреймворка. Список берётся из той версии, на которую идёт обновление, поэтому новая версия сама может добавить пути.
- `tools/kit-update.sh <remote|путь> <тег>` отказывается работать при грязном дереве, забирает тег и заменяет только эти пути. Затем показывает `git diff --stat`. Коммит делает человек.
- `.kit-exclude` в корне репозитория перечисляет пути, которые форк не забирает, в том же формате, что и `tools/kit-paths.txt`.
  Запись закрывает всё внутри себя и может быть шире или уже пути из списка. Скрипт сообщает, что пропустил, и предупреждает о записи, которой ничего не соответствует.
  Файл принадлежит репозиторию и не входит в `tools/kit-paths.txt`.

Состояние инициативы вычисляется отдельно:
`tools/scripts/speckit-status.py` читает файлы, а не файл сессии.
Файлы сессий не коммитятся, поэтому без этого `/speckit-continue` останавливался на чужой машине.

## Последствия

- **Локальные правки надо переносить вручную:** в diff они выглядят как удалённые строки, и их возвращает человек. Скрипт не различает локальную правку и изменение в ките.
- **Удалённые в ките файлы остаются:** скрипт только перечисляет файлы, которых нет в новой версии. Это могут быть и собственные файлы форка, поэтому автоматически они не удаляются.
- **Исключённые пути не получают исправлений:** форк отвечает за них сам. Без исключения удалённый намеренно путь возвращался бы при каждом обновлении.
- **Первое обновление с исключениями запускается скриптом из тега:** скрипт старой версии не знает про `.kit-exclude` и вернул бы исключённые пути.
- **Миграция данных не выполняется:** при major-версии форк сверяется с `CHANGELOG.md` и переносит данные сам.
- **`/speckit-status` как отдельная команда не добавляется:** статус вызывается из `/speckit-continue` и через `make status`, число команд не растёт.
