# PLAT-0005: Реестр продукта как текущее поведение и delta-модель требований

## Контекст и постановка проблемы

После архивации инициативы не оставалось файла, который отвечает на вопрос «как продукт работает сейчас». В `requirements-registry.yml` хранились только заголовок и итоговый статус. Изменить выпущенное требование было нельзя: повторный REQ-ID считался коллизией. Слияние в реестр выполнял агент по промпту на 320 строк, поэтому его правила не проверялись тестами.

## Факторы принятия решения

- **REQ-ID стабилен:** тесты, контракты и ADR ссылаются на него, переименование ломает трассировку.
- **Конфликт виден заранее:** параллельные инициативы не должны молча затирать друг друга.
- **Слияние проверяется:** правила нужны в коде с тестами.
- **`requirements.yml` остаётся YAML:** без Markdown-дельт и новых форматов.

## Рассмотренные варианты

- **Вариант A:** Новый REQ-ID на каждое изменение. Ломает ссылки и теряет историю требования.
- **Вариант B:** Тот же REQ-ID, ревизия в реестре и поле `delta` в инициативе, слияние в скрипте.
- **Вариант C:** Markdown-дельты по образцу OpenSpec. Потребовали бы второго формата рядом с `requirements.yml`.

## Решение

**Выбранный вариант: B.**

- Реестр (`schema_version: 2`) хранит полный текст требования, `rev`, `status` и `history[]`.
- Требование в инициативе указывает `delta` и, если меняет запись, `base_rev`. Отсутствие `delta` означает `added`, поэтому существующие инициативы остаются валидными.
- `tools/scripts/graduate.py` применяет правила: сначала план в памяти, запись только при отсутствии конфликтов. Запись, в истории которой уже есть эта инициатива, не меняется, поэтому повторный запуск безопасен.
- `tools/scripts/check-deltas.py` находит те же конфликты до слияния. Для требований в статусах слияния это ошибка, для остальных — предупреждение: незавершённая работа другой команды не должна блокировать чужой PR.
- `check-trace` считает покрытие отдельно для каждой пары (инициатива, REQ-ID), потому что один ID теперь может жить в нескольких инициативах.
- Слияние контрактов пока остаётся в промпте: `git_commit` хранит базовый коммит слияния, `git commit --amend` больше не нужен.

## Последствия

- **Несовместимость:** реестр старого формата не принимается. `graduate.py` и `check-deltas.py` сообщают `REGISTRY_SCHEMA`. Конституция получает версию 3.0.0.
- **Миграция `products/platform`:** текст четырёх записей восстановлен из `c6711c2^:initiatives/INIT-2026-009-smoke-test/requirements.yml`. Scope переименован в `REQ-DEMO-*`, потому что туториал создаёт `REQ-EXPORT-*` в том же продукте и получал бы ложный конфликт. Владелец реестра заменён на `@platform-team`.
- **Модель проверена тестами, а не практикой:** реальных слияний пока почти не было. Первое реальное слияние стоит считать пилотом.
- **Не решено:** нет слияния контрактов в коде и нет проверки того, что тесты действительно проходят.
